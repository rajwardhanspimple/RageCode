Ragestar 2.2.9

What the window adds

The CLI engine still runs underneath, as a sidecar process. Tool execution, permissions and MCP servers behave the same. These are the parts you get because it's a desktop app.

Multi-lane egress

Direct, WARP, Tor and proxy lanes, each with its own health check, latency history and rotation. A failing lane doesn't stop the others, and autoRecover is off by default.

Isolated sessions

Every session keeps its own workspace, model selection and agent. Switch between two projects without reconfiguring anything.

Provider-agnostic

No endpoint in the source, no bundled key, no account. Apply a community template, add your own preset, or paste a registry URL. Nothing applies until you press Use.

Data, not code

Provider endpoints live in presets.json and community-presets.json beside the binary. Delete the file and the entries disappear.

No telemetry

The app contacts the endpoints you configured, the registry URL you loaded, and nothing else. Credentials stay in the engine's config under your user data directory.

Installers for all three

The 2.2.9 release ships the NSIS installer for Windows, a dmg and zip for macOS on arm64 and x64, and an AppImage, deb and rpm for Linux x64.

Questions

The short answers, without a marketing gloss.

Is this the official OpenCode desktop app?

No. Ragestar is an independent MIT-licensed client, not affiliated with, endorsed by or operated by OpenCode or its maintainers. The shell is an independent rewrite with its own identity, theme engine and egress manager; see NOTICE.md for upstream attribution and the list of changes.

Does it work with OpenCode?

Yes, as a community-supported engine configuration, not an official integration. Ragestar bundles an open-source CLI engine and reads provider templates from community data files; OpenCode is the upstream project that engine comes from. There is no affiliation, endorsement or support commitment in either direction.

What do I need to run it?

A provider you already have access to, or a free-tier template. On first launch there is no provider, no model and no key. Open the model chip, pick a template or add your own base URL, then paste the key that endpoint accepts. If you have no provider, the app opens and does nothing else.

Why does Windows SmartScreen warn me?

The installer is not code-signed, so SmartScreen shows the standard "unknown publisher" prompt. The 2.2.7 installer was scanned at VirusTotal with 0/50 detections; the 2.2.9 build is pending its first scan. Every artifact here has a SHA-256 in SHA256SUMS.txt. Check with Get-FileHash .\Ragestar-Setup-2.2.9.exe -Algorithm SHA256.

Why does macOS refuse to open the app?

The build is unsigned and not notarized, so Gatekeeper blocks the first launch. Open the dmg, drag Ragestar to Applications, then right-click (or Control-click) the app and choose Open, or allow it under System Settings › Privacy & Security. Check the dmg's SHA-256 against SHA256SUMS.txt first.

What is multi-lane egress?

A lane is a route out of your machine. Direct goes straight out; WARP, Tor and proxy lanes route through that transport. The egress panel shows each lane's last rotation, latency and provider result. Rotation is verified against the provider endpoint before it's recorded.

Is it free?

The application is MIT-licensed and costs nothing. You pay whatever your provider charges, if anything. There is no Ragestar account, no subscription and no upsell screen.

Does it auto-update?

Release builds from 2.2.6 on carry an app-update.yml that points at this repository's own releases and check every four hours; nothing downloads until you ask. From 2.2.9 the engine underneath can advance on its own too, but only after the candidate verifies its published integrity, boots in a throwaway data directory, serves all 25 routes the window calls, and survives a real session round trip — and a launch that never reaches its sidecar reverts to the bundled engine. Builds packaged without RAGESTAR_UPDATE_REPO — everything before 2.2.6, dev checkouts and forks — write no feed, so electron-updater stays inert. Set the variable to point a fork at its own releases.

Which providers work?

Anything that speaks an OpenAI-compatible or Anthropic-compatible API can be added as a preset entry with its base URL. Provider entries are community data files, not built-ins, and not a bypass of any service's terms — whether a given client is permitted is between you and your provider.
